## 2. 자동충전(Auto-Ceiling) 금액 산정 로직

- 기본: 1만 원 단위 올림
- 예외: 한도 충전 가능 금액이 **200P 이상 ~ 10,000P 이하** 인 경우 → 무조건 1만 단위로 full 맞춰 자동충전
- 최대 충전 가능 금액 = **200P 미만** 시 → 충전 성공 안내

**공식**
```
충전 금액 = CEILING((잔여충전금액 - 한도금액) / 10,000) × 10,000
```

### 사례 1 — 36,200원 상품 구매 시

| 현재 잔액 | 부족 금액 | 올림 처리 (1만 원 단위) | 최종 충전 금액 | 충전 및 구매 후 잔액 |
|---|---|---|---|---|
| 10,000원 | 26,200원 | 30,000원 | 30,000원 | 3,800원 |
| 35,000원 | 1,200원 | 10,000원 | 10,000원 | 8,800원 |

### 사례 2 — 2,000,000원 상품 구매 시

| 현재 잔액 | 부족 금액 | 올림 처리 (1만 원 단위) | 최종 충전 금액 | 충전 및 구매 후 잔액 | 비고 |
|---|---|---|---|---|---|
| 1,990,000원 | 10,000원 | 10,000원 | 10,000원 | 0원 | POS 결제 |
| 1,999,800원 | 200원 | 불가 | 200원 | 0원 | 2,000,000원 전액 모바일 결제 |
| 1,999,800원 | 200원 | 불가 | 200원 | 불가 | 2,000,000원 보유 한도 초과 |
| 1,999,990원 | 10원 | 불가 | 불가 | 불가 | 분할결제 요구 필요 |

## 3. 보유 한도(200만 원) 및 예외 상황 처리 정책

| 충전 유형 | 예외 상황 | 시스템 처리 정책 (Action) | 사용자 안내 (Message/UI) |
|---|---|---|---|
| **공통** (한도 상황시) | 충전 성공 시 잔액 > 50만 원 | 충전 프로세스 진입 차단 또는 실패 | 최대 50만 원까지 보유 가능 안내 문구 노출 후 차단 |
| **공통** (한도 상황시) | 충전 성공 시 잔액 > 200만 원 | 충전 프로세스 진입 차단 또는 실패 | 최대 200만 원까지 보유 가능 안내 문구 노출 후 차단 |
| **즉시 충전** | 입력 금액 자체가 한도 초과 | 입력 필드 Validation (최대값 제한) | 충전 버튼 비활성화 및 하단 안내 문구 노출 |
| **자동 충전** | Case1) 남은 충전 한도 < 1만 원 | Case1) 1만 원 단위 올림 충전 | Case1) 팝업 도달 없음 → 충전 성공 |
| | Case2) 한도 충전 한도 200원 < 1만 원 | Case2) 한도까지 1만 단위로 정밀 충전 (최소 금액 200원) | Case2) 팝업 도달 없음 → 충전 성공 |
| | Case3) 남은 충전 한도 200원 미만 | 충전불가 안내 팝업 | Case3) 충전불가 안내 팝업 노출 후 페이지 이동 |
| **예약 충전** | 배치 시점에 잔액 한도 초과 예상 | 해당 유저의 배치 스킵 (Skip) 처리 | 보유 한도 초과로 예약충전 실패 문구 노출 — 앱푸시 발송 |
| **예약 충전** | 2월 30일 등 존재하지 않는 지정일 | 해당 월의 말일에 충전 배치 실행 | 날짜 입력 화면에 추가 안내 문구 노출 |
| **자동/예약** | 빌링키 유효성 상실 (카드 재발급 등) | 충전 실패 | 결제 수단 정보 유효하지 않음으로 충전 실패 문구 노출 — 앱푸시 발송 |
