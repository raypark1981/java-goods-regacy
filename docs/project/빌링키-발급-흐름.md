# 빌링키 발급 흐름

> 자동충전 결제 전 사전 단계. 계좌 등록 화면에서 1회 수행되며 발급된 `billingKey`를 DB에 저장한다.  
> 현재 자동충전 결제 API 작업 범위에서는 **제외** (billingKey가 이미 저장된 상태를 전제로 함)

---

## 흐름도

```
[고객]                  [프론트]                  [토스]                  [Java 서버]              [DB]
  |                       |                         |                         |                    |
  |-- 계좌 등록 요청 ----->|                         |                         |                    |
  |                       |-- requestBillingAuth() ->|                         |                    |
  |                       |   (clientKey, customerKey)                         |                    |
  |<-- 계좌 인증창 --------|<-------------------------------- 인증창 응답 -------|                    |
  |                       |                         |                         |                    |
  |-- 계좌 인증 완료 ----->|                         |                         |                    |
  |                       |                         |-- successUrl 리다이렉트 ->|                    |
  |                       |                         |  ?authKey=&customerKey=  |                    |
  |                       |                         |                         |-- 빌링키 발급 API ->|
  |                       |                         |                         |  POST /v1/billing/  |
  |                       |                         |                         |  authorizations/    |
  |                       |                         |                         |  issue              |
  |                       |                         |<----------------------- billingKey 응답 ------|
  |                       |                         |                         |                    |
  |                       |                         |                         |-- BILL_KEY 저장 --->|
  |                       |                         |                         |  AP_CUST_CHRG_      |
  |                       |                         |                         |  ACNT_MNG           |
```

---

## 단계별 설명

### 1. 프론트 — 계좌 인증창 호출

토스 JavaScript SDK v2로 `requestBillingAuth()` 를 호출한다.

```javascript
const tossPayments = TossPayments(clientKey);
const payment = tossPayments.payment({ customerKey });

await payment.requestBillingAuth({
    successUrl: window.location.origin + "/billing/success",
    failUrl:    window.location.origin + "/billing/fail",
    customerEmail: "customer@example.com",
    customerName:  "홍길동",
});
```

| 파라미터 | 설명 |
|---------|------|
| `clientKey` | 토스 SDK 초기화용 공개 키 (환경별 관리) |
| `customerKey` | 우리 서비스 고객 식별값 (회원번호 기반 생성, 개인정보 원문 사용 금지) |

---

### 2. 토스 — successUrl로 authKey + customerKey 전달

계좌 인증 완료 후 토스가 `successUrl`로 리다이렉트하며 쿼리 파라미터를 전달한다.

```
GET /billing/success?authKey={authKey}&customerKey={customerKey}
```

| 파라미터 | 설명 |
|---------|------|
| `authKey` | 토스가 발급한 1회성 인증 키. 빌링키 발급 요청에 사용 |
| `customerKey` | 인증 요청 시 전달했던 고객 식별값 |

---

### 3. Java 서버 — 빌링키 발급 API 호출

`secretKey`로 Basic 인증 후 토스 빌링키 발급 API를 호출한다.

```
POST https://api.tosspayments.com/v1/billing/authorizations/issue
Authorization: Basic base64("{secretKey}:")
Content-Type: application/json

{
  "authKey":     "{authKey}",
  "customerKey": "{customerKey}"
}
```

> `secretKey`는 환경변수로 관리. 소스/로그/응답에 절대 노출 금지.

응답 예시:

```json
{
  "billingKey":  "Z_t5vOvQxrj4499PeiJcjen28-V2RyqgYTwN44Rdzk0=",
  "customerKey": "customer_001",
  "method":      "계좌",
  "card": null
}
```

---

### 4. Java 서버 — billingKey DB 저장

발급받은 `billingKey`를 `AP_CUST_CHRG_ACNT_MNG.BILL_KEY`에 저장한다.  
암호화/마스킹 적용 권장.

| DB 컬럼 | 저장값 |
|--------|------|
| `MCUST_NO` | 통합고객번호 |
| `CUST_KEY` | customerKey |
| `BILL_KEY` | billingKey (암호화 저장 권장) |
| `BANK_GBCD` | 은행구분코드 |

---

## 키 사용 범위 요약

| 키 | 사용 단계 | 노출 범위 |
|----|---------|---------|
| `clientKey` | 1단계 — 프론트 SDK 초기화 | 프론트 노출 가능 |
| `customerKey` | 1·2·3단계 | 프론트 전달 가능 (개인정보 원문 금지) |
| `authKey` | 2·3단계 | 서버 수신 후 즉시 사용, 저장 불필요 |
| `billingKey` | 3단계 이후 — 자동결제 시 사용 | 서버 내부만. 외부 노출 절대 금지 |
| `secretKey` | 3단계 — 토스 API 인증 | 환경변수 관리. 소스/로그 노출 금지 |
