## 토스 자동결제 키 정리

자동충전 결제에서는 계좌 등록/빌링키 발급 단계와 실제 자동결제 호출 단계를 구분해서 키를 사용한다.

| 키 | 역할 | 노출 가능 범위 | 저장 추천 방식 | 자동충전 결제에서의 사용 |
|---|---|---|---|---|
| `clientKey` | 토스 SDK 초기화용 공개 키 | 프론트/JSP/JavaScript 노출 가능 | 환경별 설정값으로 관리. 운영/개발 키 분리 | 계좌 등록 화면에서 토스 결제창 또는 빌링 인증창 호출 시 사용 |
| `customerKey` | 우리 서비스의 고객 식별값 | 프론트 전달 가능. 단, 주민번호/전화번호/이메일 등 개인정보 원문 사용 금지 | 회원번호 기반의 내부 고유값으로 생성 후 DB 저장 또는 재생성 가능 규칙으로 관리 | 토스에 “어느 고객의 결제수단인지” 식별시키는 값 |
| `billingKey` | 토스가 발급하는 자동결제용 결제수단 키 | 외부 노출 금지. 서버 내부에서만 사용 | DB 저장. 가능하면 암호화/마스킹 적용, 회원 식별값과 매핑 | 자동충전 시 서버가 토스 빌링 결제 API를 호출할 때 사용 |
| `secretKey` | 서버에서 토스 API 호출 인증에 사용하는 비밀 키 | 절대 노출 금지. 프론트/JSP/로그/응답 포함 금지 | 환경변수, 서버 설정, Secret Manager 등으로 관리. 소스/문서/DB 저장 금지 | 빌링키 발급, 결제 승인, 결제 취소, 결제 조회 API 인증에 사용 |

### 키 사용 흐름

1. 계좌 등록 화면에서 `clientKey`로 토스 SDK를 초기화한다.
2. `customerKey`를 사용해 회원 결제 객체를 만들고 빌링 인증을 요청한다.
3. 인증 성공 시 토스가 `authKey`, `customerKey`를 성공 URL로 전달한다.
4. Java 서버가 `secretKey`로 인증해서 `authKey + customerKey`를 토스에 보내고 `billingKey`를 발급받는다.
5. 발급받은 `billingKey`를 회원의 자동충전 결제수단으로 저장한다.
6. 자동충전 발생 시 Java 서버가 `secretKey + billingKey`로 토스 빌링 결제 API를 호출한다.

## VO/함수명 축약어 사전

함수명이나 VO 이름을 해석할 때 아래 축약어를 기준으로 역할을 유추한다.

| 축약어 | 의미 | 한글 의미 | 비고 |
|---|---|---|---|
| `Prpy` | Prepaid | 선불 | 선불카드/선불충전 계열 |
| `Crd` | Card | 카드 | 카드 |
| `Chrg` | Charge | 충전 | 포인트/선불 충전 |
| `Gc` | Gift Card / Gift Certificate | 상품권 | 상품권 계열 가능성 높음 |
| `Prsn` | Person / Personal | 개인 | 문맥상 개인/개인회원 계열 |
| `Req` | Request | 요청 | 요청 전문/요청 VO |
| `Res` | Response | 응답 | 응답 전문/응답 VO |
| `Reg` | Register | 등록 | 등록 처리 |
| `Use` | Use | 사용 | 포인트/카드/상품권 사용 |
| `Refer` | Refer / Reference / Retrieve | 조회 | 문맥상 조회로 해석 |
| `Exchg` | Exchange | 교환 | 교환 처리 |
| `Comm` | Common | 공통 | 공통 전문/공통 필드 |
| `VO` | Value Object | 값 객체 | 요청/응답 데이터 객체 |

예시:
- `PrpyCrdChrgReqVO`: 선불카드 충전 요청 VO
- `PrpyGcExchgResVO`: 선불 상품권 교환 응답 VO
